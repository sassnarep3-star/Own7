Method & limits

The six rules this desk works under, how to reproduce every number, and the limits that constrain every conclusion.

The rules this desk works under

  1. Never infer a value. If no official source publishes it, the cell is empty with a machine-readable marker, and a test asserts the cell is truly blank.
  2. Every table row links its source. A row that cannot link an official page does not get published.
  3. Recompute what can be recomputed. Every club row is re-derived from its own printed numbers, and the league identity must balance or the build aborts.
  4. Separate the quantity from the label. Club-level correlation is not leg correlation. A printed rank is not a point value. A Pythagorean residual is not proof of luck.
  5. Test the maths against published tables. The chi-square, normal, Student-t and incomplete-beta implementations are checked against reference values, so a silent break in the statistics fails the build.
  6. Publish the irregularity. A source that contradicts itself goes on the flagged page with a link, not into a footnote.

How a player is matched to a depth slot

Three precedence rules, applied in order, and published because they decide which backup the site names:

  1. The newest chart read wins. A 2026-11-14 capture is never displaced by a 2026-11-12 one.
  2. A slot whose position group agrees with the injury report beats one that does not. Clubs and the league use different vocabularies for the same job - the chart prints RT, LT, EDGE, SAM, ILB, NCB; the report prints T, DE, LB, CB. Grouping them (T/RT/LT/G/C as OL; DE/DT/NT/EDGE as DL; LB/ILB/MLB/SAM/WLB as LB; CB/S/NB as DB) is what keeps a receiver listed by the league at WR from being located by his punt-return slot.
  3. Then the higher printed rank wins.

This mattered: before the group rule, 118 of 265 matched rows carried a different position label on the chart than the league reported, and several were on the wrong side of the ball entirely - a receiver located at PR, a linebacker at SAM. That silently moves a player between the offence and defence columns of the depletion index. After the rule, zero matched rows sit on the wrong side of the ball, and a test asserts it.

The rule never invents a role. It only chooses between slots the club itself printed.

Reproduce every number

Python 3.11+, standard library only. From the repository root:

cd nfl-skill-cfdd
python collect.py       # standings, arithmetic + identity checks
python depth.py         # the 4 newly captured charts
python index.py         # depletion join, all 32 clubs
python luck.py          # overdispersion, sample size, correlations
python ledger.py        # strategies and computed gates
python decisions.py     # questions, suggestions, flags
python build.py         # regenerate this site
python -m unittest discover -s tests -v

Each script supports --check, which re-derives its artifacts in memory and fails if a committed file is stale. CI runs all of them plus the repository-wide link and source audit.

Limits, stated plainly

  • One partial season. Eight or nine games per club. No persistence can be measured, and no strategy can be called skill based.
  • No price, no ROI, no CLV. NFL.com publishes no odds and the rights question is unsettled. These cells are blank by rule and a test enforces it.
  • No leg dependence. No settled ticket exists, so parlays and prop combos cannot be priced at all.
  • No point value for an injury. A printed rank is an ordering. Converting it to points needs snap counts and a before/after series, which are not retrieved.
  • Single-source availability. The league injury page is one publisher. At least one club disagrees with it in public, so the aggregate is not treated as complete.
  • Rendered-text evidence. Not an HTTP archive. It proves what the page said; it cannot prove what else the page said.
