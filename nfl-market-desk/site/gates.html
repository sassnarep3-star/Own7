Validation & demotion

Ten gates that can each fail, and a demotion gate with five numeric triggers that sends a live strategy back to paper.

10/10gates passing, computed not declared
5demotion triggers, all numeric
0strategies live
0demotions in production — nothing is live yet

A gate is only real if it can fail

Each gate below is a function of the published data. None is hard-coded to pass: a missing input returns blocked, never pass. The evidence column is the computation's own output, so a reader can see what decided each status.

Requirement 8: the demotion gate

Any strategy reaching the live tier is subject to 5 numeric triggers. Any one firing returns it to paper. Promotion back requires a fresh out-of-sample window that clears every promotion gate again.

Status: armed, exercised, not yet triggered in production. Nothing is live, so no real demotion has occurred. That distinction matters and is not glossed: the gate has been proven to fire on a probe ledger, which is not the same as having governed a live strategy.

An input that cannot be evaluated is itself treated as a demotion trigger, because an unverifiable live strategy is not a live strategy.

Promotion, separated from staking

The promotion function receives signal fields only. Staking fields are explicitly excluded, and the function raises if one appears — a check that is exercised on every build, and the evidence for gate MD-G06 above is the raise itself.
